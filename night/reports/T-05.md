# T-05 — Performance on slow computers
Status: done (partially meets the 200 ms target; see below)

## What changed
Finished by hand in the same session as T-09 (the night shift was stopped). Details, numbers and
method in `docs/performance.md`.
- `lib/farms.worker.ts` + `lib/farms.ts`: the municipality farms are decompressed and parsed in a
  Web Worker; the main thread gets properties, bounding boxes and lazily parsed geometries; MapLibre
  loads the GeoJSON from a `blob:` URL in its own worker (`controller.ts` `setData(url)`).
- `lib/detail.worker.ts` + `lib/detail.ts`: the detail files are parsed and kept in a worker; only
  the requested farms reach the main thread. `loadDetails()` keeps its signature.
- `diorama.ts`, `clouds.ts`: `renderer.debug.checkShaderErrors` only in development.
- `e2e/perf.spec.ts`: the measurement (opt-in with `PERF=1`; `PERF_PROFILE` saves a CPU profile).

## How it was verified
- Before / after with CPU ×4 + Fast 3G (table in `docs/performance.md`): opening a farm, longest
  task 2755 → 1867 ms (3647 with the workers only), blocking 7.6 → 5.3 s; back to the municipality
  1183 → 796 ms; opening Antequera 2158 → 1771 ms.
- CPU profiles of "Open farm" before and after the shader change.
- `tsc -b`, build, calculator check, unit tests and the full e2e suite (see the T-10 report).
