# T-09 — Accessibility - keyboard, screen readers, text size, contrast mode
Status: done

## What changed
The night shift's agent built the accessibility layer (commits `9101ab7` … `62c21a3`); the session that
finished the ticket (by hand, on another machine, after the shift was stopped) ran the full suite,
fixed the four problems it found and wrote this report.

1. **Keyboard alternative to the map** (`AccessList.tsx`, `listing.ts`): on every level an
   accessible combobox + listbox (accent-insensitive search, ↑/↓/Home/End move the highlighted option
   with `aria-activedescendant`, Enter opens, Esc closes the list first). Provinces → municipalities →
   farms; the farm list holds farmland only (urban / water / public farms are not listed), candidates
   first, then by area; limited farms (forest, steep, rock) are listed and open with a warning.
2. **Screen readers** (`messages.ts`, `Explorer.tsx`, `FarmTable.tsx`, `tableRows.ts`): an
   `aria-live` region announces "Going to …" and "Step N of 4: …" on arrival; the map region has a
   text summary; the 3D canvas is described as an image and is not a Tab stop; a real data table
   (indicators per rotation, rank, best for the chosen priority) is available next to the 3D and
   replaces it when the 3D is off.
3. **Settings menu** (`SettingsMenu.tsx`, `settings.ts`, `access.css`): text size 100 / 125 / 150 %
   (`--ts` scale on every explorer font size and the root font size for rem-based parts), high
   contrast, reduce motion (also follows `prefers-reduced-motion`), 3D on/off (off: flat map, data
   table, three.js is never downloaded). Persisted in `localStorage` key `ciberpiso.settings.v1`;
   every access is wrapped in try/catch and corrupt values fall back to the defaults.
4. **Focus management** (`Explorer.tsx`, `useFocusTrap.ts`): after each transition focus moves to the
   new level's `h1`; Esc goes up one level; the "Full data" drawer and the Settings panel are dialogs
   that trap Tab / Shift+Tab, close with Esc and return focus to the button that opened them.
5. **Touch targets** ≥ 44×44 px on phones (timeline years, rotation buttons, list options, settings).

Fixes made while finishing the ticket (found by the e2e suite on Linux, where the fallback fonts
have taller glyph boxes than on macOS, which exposed real overlaps):
- **Heading focus indicator**: the 3 px outline around the focused `h1` crossed the tall serif
  glyphs (measured contrast 1.22:1 for the heading text). It is now a 4 px accent bar beside the
  heading (`access.css`), which never touches the text.
- **Current year in the timeline**: the 4 px ring of the selected crop chip touched the year label
  below it (contrast 1:1 on "25"). Gap between chip and label 4 → 7 px (`explorer.css`).
- **"Best" star badge**: the ★ glyph came from a fallback font whose box spilled outside the 17 px
  badge (2.42:1). It is now an inline SVG star (same look on every OS, still `aria-hidden`).
- **Focus race after a transition**: the heading got focus 60 ms after the transition ended, even if
  the person had already moved focus (e.g. opened "Full data", whose close button then lost focus).
  On a slow computer that timer fires late. Now the heading only takes focus if nobody moved it in
  the meantime (`Explorer.tsx`).

### Keyboard-only journey (exact key sequence)
1. Load the page. `Tab` until the combobox "Choose a province from the list". Type `mal`,
   `Enter` → Málaga. Focus lands on the heading "Choose the
   municipality"; the live region says "Step 2 of 4: Málaga…".
2. `Tab` to "Choose a municipality from the list", type `anteq`, `Enter` → Antequera (focus on the
   heading "Antequera", "Step 3 of 4").
3. `Tab` to "Choose a farm from the list" (opens on focus; `↓`/`↑` move), type `62-14`, `Enter` →
   farm 62-14 (focus on its heading, "Step 4 of 4: Farm 62-14").
4. `Tab` through the farm view: insights, cards, timeline years, rotations R0–R3, priority, Back,
   view and zoom toggles, Data table, Full data, Settings (every stop has a name and a visible ring).
5. `Esc` three times → Antequera → Málaga → Andalucía (focus on each heading).

## How it was verified (commands and results)
Linux (Fedora), Node 22, Playwright 1.65.1 with its headless Chromium (`E2E_BROWSER=chromium`; no
Google Chrome on that machine), WebGL through SwiftShader.
- `npx tsc -b` → OK. `npm run build` → OK. `node scripts/check-calculator.ts` → 1144 values, 0 differences.
- `npm run test` → 5 files, 174 tests passed. `npx oxlint src` → 2 warnings (`set-state-in-effect`
  in the unused `MapView.tsx` and in `AccessList.tsx`), no errors.
- Full e2e suite before the fixes: 113 passed, 10 failed (5 text-contrast, 1 drawer focus, 1 tablet
  "Full data" click covered by the director panel, 2 phone touch targets, 1 high-contrast). All ten
  are the problems listed above plus two more fixed here:
  - phone: the indicator cards (`article.fx-card[tabindex=0]`) were 37 px tall → `min-height: 44px`;
  - phone: the "Scenario R1" label was absolutely placed over the second row of years → it is now
    a real element in its own grid row (`.scn-lbl`, desktop keeps `.years::after`);
  - tablet 1024×768: the farm tools wrap to two rows since "Data table" was added, and the
    director panel (testing only) covered "Full data" → the panel sits below them at that width;
  - the heading focus bar did not apply at first: `.xp :is(…, [tabindex]):focus-visible` is more
    specific than `.xp h1:focus-visible`, so the rule is `.xp h1[tabindex]:focus-visible`.
- After the fixes: `npx playwright test colour touch settings keyboard` → 67 passed;
  `npx playwright test layout -g "mobile|tablet"` → 18 passed;
  `npx playwright test layout flows a11y` (desktop / 1280 / 1440 layouts, flows, accessible names) → 49 passed.
